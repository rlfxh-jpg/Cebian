# 本地文件夹工作台需求文档

状态：需求定义，尚未实现。

## 1. 背景与目标

新增一个 WXT 未登记页面，作为独立标签页打开。用户连接本机 WebSocket 服务并指定一个本地文件夹后，可以在页面左侧实时浏览目录树，在右侧打开和编辑文本文件，并完成新建、保存、删除、重命名。

页面负责连接状态、目录树和编辑界面；本地服务负责访问及监听文件系统。仅靠扩展页面无法凭一个路径字符串持续读取任意本地目录，因此本地服务是完整功能的必要交付物。

每个页面首版只选择一个根目录，所有文件操作限定在该目录内；多个页面可以分别选择目录，也可以订阅同一目录。此页面不接入现有 VFS、聊天会话或后台 IPC。

## 2. 交付物与代码边界

1. 在 `entrypoints/local-folder/` 增加 WXT 未登记页面。WXT 自动发现该目录的 `index.html`，构建后页面通过 `browser.runtime.getURL('/local-folder.html')` 访问；无须登记为弹窗、侧边栏或设置页。
2. 增加独立运行的本地服务，以 WebSocket 向页面提供目录读取、文件操作和变化通知。页面不能自行启动服务；服务安装与启动方式须在实施阶段明确交付。
3. 不修改现有 TS/TSX 业务代码、VFS 行为或 WXT 配置。新页面和服务的实现放在新增文件中。
4. 允许复用确实适合的现有通用能力及已安装的第三方依赖，以正确、简洁地完成需求为优先。现有 `components/editor/FileTree.tsx` 和 `components/settings/sections/EditorPanel.tsx` 直接绑定 VFS，不能直接接到本地服务上；新页面需要自己的目录树数据层和保存流程。
5. 可复用现有 i18n 运行时来读取生效语言和已有通用文案。新页面专属文案放在入口自己的英文、简体中文、繁体中文资源中，不要求修改现有翻译文件；需对新资源做键完整性和占位符一致性校验。
6. 本地服务负责文件夹选择、最近使用目录、目录查询、文件操作、文件名搜索与监听订阅。页面负责多文件标签、编辑状态、搜索交互及草稿恢复；两者通过版本化协议协作。

未登记页面仍与本扩展其他页面共享扩展来源和 manifest。本需求中的“隔离”指代码与功能边界，不表示浏览器权限沙箱或独立扩展身份。

## 3. 用户流程

### 3.1 首次连接与选择目录

1. 页面显示本地服务地址、连接状态和首次配对入口。服务未运行、未配对或授权被撤销时分别显示可操作的状态。
2. 连接并完成配对后，用户可通过本地服务提供的系统文件夹选择器选择根目录，也可输入绝对路径。文件夹选择器取消时不改变当前监听目录。
3. 页面列出最近使用的目录，允许快速重新打开及移除记录。最近记录只用于选择，不代表永久授权；目录不存在或不可访问时显示原因，并允许移除记录。
4. 本地服务验证路径存在、属于目录且可访问，建立监听并返回根目录信息。页面加载根目录第一层条目，随后按用户展开操作加载子目录。
5. 目录切换时，若任一标签有未保存内容，先提示用户处理；确认后取消本页面对旧目录的订阅、启动新目录订阅并清空旧目录视图。其他页面的订阅不受影响。

### 3.2 浏览与打开

- 左侧目录树支持展开、折叠、选中、键盘操作、长名称提示及独立滚动；文件夹排在文件前，同类按名称排序。
- 子目录按需加载，避免对大型目录一次性递归扫描。空目录、读取中、读取失败分别有明确状态。
- 提供手动刷新目录操作，刷新时保留仍存在的展开状态和选中项；服务还需定期校验已展开目录，补偿文件监听器漏报。
- 提供按文件名搜索和键盘快速打开。结果展示相对路径以区分重名文件；选择结果后定位目录树并打开文件。搜索不得要求页面先展开整棵树。全文搜索不在首版范围内。
- 点击文本文件后，右侧以标签页显示文件名、相对路径、大小、内容及加载状态。可同时打开多个文件、切换与关闭标签；各标签独立维护编辑内容、保存状态和磁盘版本。旧请求的迟到响应不得覆盖新选择或其他标签。
- 未选中文件、文件已删除、无权限读取、非文本文件、文件过大及服务断开均有明确提示。
- 首版只处理文本，不执行 HTML、SVG 或脚本内容，也不提供二进制预览。无扩展名文件按实际内容判断是否为文本；隐藏文件默认显示，按与普通文件相同的规则操作。符号链接须明确标识，指向根目录外或无法解析时不可进入、读取或修改。非 UTF-8 文件明确显示编码不支持，不得以有损解码内容写回。预览上限建议为 5 MiB，实施时固定具体阈值，并由服务端强制执行。
- 提供忽略规则配置，明确区分“仅在树中隐藏”和“停止监听、索引及搜索”两种效果。规则变更后刷新相关目录与搜索结果；被忽略项仍在磁盘上，不得被当作已删除。`node_modules`、`.git` 等目录可作为建议规则，但用户能查看并修改实际生效的规则。

### 3.3 新建、编辑与保存

- 在选定目录下可新建空文本文件或文件夹。提交前校验名称为空、非法字符、重名和目标目录权限；服务端再次校验。
- 文本文件在右侧可编辑。每个标签分别显示未保存、保存中、已保存和保存失败状态；有未保存修改的标签须有可识别标记。
- 首版采用显式保存，提供保存按钮及 `Ctrl/Cmd+S`；编辑时不自动写盘。保存失败不得清除用户输入。
- 读取时识别 UTF-8 BOM、`\n`/`\r\n` 换行风格与末尾换行；保存时保留原有格式，不因局部编辑而无提示地改写整份文件的换行或 BOM。原文件混用换行时须明确处理策略，不能静默将所有行规范化。
- 关闭含未保存内容的标签、切换监听目录或关闭页面前应提示用户；单纯切换标签或刷新目录树不触发丢弃提示。连接中断时保留所有标签的未保存内容。
- 为未保存的文本建立有期限的本地草稿。页面意外关闭或重开后，检测到草稿时由用户选择恢复或丢弃；草稿不得自动覆盖磁盘版本。草稿与目录、文件路径及基础版本关联，并在成功保存、用户丢弃、过期或授权撤销时清理。页面应说明草稿存放在扩展本地存储中；不记录已保存文件的完整副本。
- 新建和保存进行中，暂时禁用同一目标的重复操作；失败后恢复可操作状态并保留输入。不同文件的独立操作不应相互阻塞。
- 只读或无法写入的文件仍可打开，但编辑区应显示不可保存的原因。

### 3.4 重命名与删除

- 文件和文件夹均可重命名。重命名只改变名称，不提供跨目录移动；不允许覆盖已有目标。
- 监听根目录本身不可通过页面重命名或删除。
- 重命名已打开文件或其父目录后，目录树选中项、所有受影响的标签路径及其草稿关联同步更新。操作失败时保留原状态并显示原因。
- 文件和文件夹均可删除。删除前显示目标名称；非空文件夹须显示受影响条目数，明确提示递归删除并要求确认。无法完整统计时不得显示不准确的确定数量。
- 删除已打开文件或包含已打开文件的目录前，先处理相关标签的未保存内容；删除成功后关闭受影响标签。删除失败时不得从目录树中永久移除目标。
- 重命名、删除进行中暂时禁用同一目标的重复操作；失败后恢复原状态及操作入口。

## 4. 实时同步与冲突处理

- 本地服务监听根目录下的新增、修改、删除和重命名。重命名可以表示为旧路径删除与新路径新增；页面最终状态必须与磁盘一致。
- 服务按规范化后的根目录共享文件系统监听；两个页面订阅同一目录时只建立一份监听，并向两边推送变化。每个页面独立维护展开状态、标签和未保存草稿；页面关闭只解除自己的订阅。
- 页面自己发起的操作也会产生文件监听事件。客户端以服务端确认的版本和事件版本归并更新，避免重复插入、重复提示或短暂回退。
- 已打开文件没有未保存修改时，外部修改后自动重新读取并更新对应标签内容。
- 已打开文件有未保存修改时，外部修改不得覆盖该标签的编辑内容；页面提示磁盘版本已变化，其他标签不受影响。
- 读文件响应包含版本标识。保存必须携带读入时的版本；磁盘版本不同、文件被删除或重命名时，服务端拒绝旧版本写入。页面保留编辑内容，提供重新加载磁盘版本或经明确确认后覆盖的处理方式。首版不要求自动合并。
- 连接中断时保留已显示内容并标明它可能过期。重连、事件版本缺口或文件监听器溢出后重新获取受影响目录；无法确定范围时重新同步整棵树。
- 定期校验已展开目录与服务端实际条目；发现漏报时自动对齐目录树。手动刷新须在断线恢复后可用。
- 服务重启、监听目录被移走或权限失效须显示真实错误状态，不能表现为空目录。

## 5. 本地服务与 WebSocket 协议

### 5.1 服务边界

- 默认仅绑定 `127.0.0.1`，端口可配置，不默认向局域网开放。
- 服务验证连接来源并要求配对凭据；不能仅凭请求来自 localhost 就允许读取或修改文件。首次配对需由本机用户在服务端确认或获取一次性配对码，页面提交后才取得授权；服务和页面分别安全保存必要凭据，重启后可继续使用。用户可在服务端撤销授权；撤销后现有连接及已存凭据立即失效，页面须重新配对。
- 服务端对每次读、写、删除、重命名及列目录重新验证相对路径，拒绝 `..`、绝对路径注入及符号链接逃出监听根目录。
- 服务端对文件名搜索、目录选择、最近目录重开及忽略规则同样执行授权与根目录边界校验；不能借搜索或规则绕过读写限制。
- 服务端限制单次文件读取大小、消息体积和事件推送频率；密集事件可合并，但最终同步必须正确。
- 服务端按目录复用监听与必要的索引，负责清理已断开的连接、不再使用的监听器及索引；不能因多开页面对同一目录重复全量扫描。

### 5.2 最小协议能力

| 类别 | 能力 |
| --- | --- |
| 连接 | 握手、协议版本协商、首次配对、授权状态与撤销通知；版本不兼容时明确报错。 |
| 监听 | 打开、关闭或切换本页面的根目录订阅；返回监听 ID、根目录信息和当前版本；同目录订阅共享服务端监听器。 |
| 查询 | 列出某目录的直接子项；读取文件内容、格式及版本；按文件名搜索；获取最近使用目录。 |
| 修改 | 新建文件、新建文件夹、按预期版本保存文件、重命名、删除。 |
| 选择与配置 | 打开本机文件夹选择器；管理最近使用目录；读取和修改隐藏/停止监听规则。 |
| 推送 | 条目新增、修改、删除及监听失败事件；事件包含监听 ID、相对路径和递增版本。 |

每个请求带唯一 ID，响应关联该 ID。客户端发送的文件目标统一为相对监听根目录的路径；绝对路径仅用于首次选择根目录。修改请求需要明确的成功结果或机器可区分的错误码，例如重名、版本冲突、权限不足、目标不存在、路径越界。

## 6. 质量要求

- Chrome MV3 与项目支持的 Firefox 构建都需验证实际本机 WebSocket 连接。浏览器可能存在本地网络或 CSP 限制，以目标浏览器实测为准。
- 大目录应保持可操作：目录按需加载、树节点虚拟化或等效处理；事件风暴不能使页面长期卡死。
- 文件名搜索和忽略规则在大型目录下仍须有界：服务端限制结果数量，并能取消过期查询；“停止监听”规则还要阻止对应目录进入监听及搜索索引。
- 页面显示的远端文件内容必须作为文本渲染，不能注入为可执行 HTML。
- 所有破坏性操作需有明确确认；重名和版本冲突不得静默覆盖磁盘内容。
- 草稿只存未保存内容，需有明确保留期限和清理机制；未重新授权时不能通过草稿恢复绕过文件操作授权。
- 新页面的英文、简体中文和繁体中文界面文案须与现有术语一致，并满足键和占位符校验。

## 7. 验收标准

1. 构建后可打开 `/local-folder.html`；现有 VFS、设置页和侧边栏行为不变。
2. 首次配对、重启后恢复连接和撤销授权均按预期工作；撤销后旧连接不能继续读写。
3. 可用系统选择器、手动输入路径或最近使用目录打开多级目录；目录树可逐级展开、手动刷新，文件名搜索能定位未展开目录中的文件。
4. 可同时打开多个 UTF-8 文本标签；新建文件、新建文件夹、编辑并显式保存、重命名、删除均在磁盘和页面上得到一致结果，重复点击不会重复执行同一操作。
5. 编辑带 BOM、CRLF 和末尾换行的文件后，只产生预期内容变化；混合换行文件不会被无提示地整体规范化。无扩展名、隐藏、符号链接和非 UTF-8 文件均按文件类型边界处理。
6. 外部程序增删改文件后页面最终同步；监听器漏报可经定期校验或手动刷新恢复；未编辑标签自动更新，有未保存修改的标签不被覆盖。
7. 两个页面订阅同一目录时共用服务端监听并都能收到变化；各自的展开状态、标签和草稿互不影响。
8. 两方同时修改同一文件时，旧版本保存被拒绝，页面保留用户编辑内容并提供冲突处理操作。
9. 关闭含未保存修改的页面后重开，能选择恢复或丢弃未过期草稿；保存、丢弃、过期或撤销授权后草稿按规则清理。
10. 隐藏规则和停止监听规则效果不同，规则调整后目录树与搜索结果同步；删除非空目录前显示准确的影响范围或说明无法完整统计，根目录不可删除或重命名。
11. 服务停止、重启，页面刷新，目录被移走及短时间大量文件变化后，页面能恢复一致状态或明确显示错误。
12. 路径穿越、符号链接越界、重名、无权限、非文本和超大文件不能造成越权读写、静默覆盖或页面崩溃。

## 8. 实施约束

本文件仅记录需求，不代表功能已实现。后续实施应先按仓库 `AGENTS.md` 提交计划并获得批准，再按子任务逐项实现、审查和验收。整个功能完成后，如最终行为相对最近发布版本有用户可见变化，按仓库规则更新 `CHANGELOG.md` 的 `Unreleased` 部分。
